# 우리의 결혼 기록

GitHub Pages에서 운영하는 두 사람의 결혼 준비·기록 웹앱입니다.

- 사이트: https://gmlduqzhd123-lab.github.io/Wedding/
- 저장소: https://github.com/gmlduqzhd123-lab/Wedding
- 메뉴: 홈, 청첩장, 우리의 일대기, 포토 앨범, 스튜디오, 신혼여행
- 서버·데이터베이스·외부 API·유료 호스팅 없이 HTML, CSS, JavaScript와 JSON으로 동작합니다.

## 지금 들어 있는 내용

스튜디오 30개 비교 항목, 대표 샘플 썸네일 60장, 장단점, 자료에 적힌 추가금, 연락처가 들어 있습니다. 연락처 22개 항목을 제공된 아모르웨딩홀 목록에 연결했습니다. 나머지 8개 항목은 미기재입니다. 관심 스튜디오와 개인 메모는 현재 브라우저에만 저장됩니다.

예식은 2026-11-08 사용자의 변경 요청에 따라 2027년 6월 5일 토요일 오후 3시, 순천아모르웨딩컨벤션 1층으로 입력했습니다. 신혼여행은 사용자 제공 자료를 바탕으로 발리·오아후·로마/피렌체·바르셀로나/마요르카·몰디브 다섯 후보를 채웠습니다. 한국 출발 2027년 5월 9일, 한국 도착 목표 5월 17일, 성인 2명·상한 1,000만 원은 기존 자료의 가안이며 변경된 예식일 기준 여행 날짜 재확인이 필요합니다. 금액은 계획 배분이며 실제 견적이나 예약 확정 정보가 아닙니다. 상세 근거와 적용 범위는 [CONTENT_SOURCES.md](CONTENT_SOURCES.md)에 기록했습니다.

두 사람의 이름·개인 사진·일대기·예식장 상세 주소는 아직 제공되지 않아 비워 두었습니다. 스튜디오 샘플을 개인 포토 앨범으로 사용하지 않습니다.

신혼여행의 날짜·총액·항공/숙박/기타/예비비 배분은 항목별로 저장하고 화면의 조건·합계·잔액·초과 안내를 같은 값에서 표시합니다. 총액과 세부 배분이 다르면 미배분 또는 배분 초과를 표시하며 차이를 임의로 비용 항목에 넣지 않습니다. 비어 있는 금액은 0원과 구분합니다. 초기 자료를 담은 이전 형식의 초안은 항목별로 변환하고 원문을 백업 데이터에 보존합니다. 직접 작성한 자유 메모의 문장까지 자동 수정하지는 않습니다.

여행 상세는 조건·숙박/이동/일정·비용·경험·기후·계획 자료로 나눴습니다. 비교표에는 숙박 가안과 비용 배분·이동·기후를 추가했고, 선택 버튼을 눌러도 펼침 상태와 읽던 위치를 유지합니다. 청첩장의 미입력 이름·초대 인사·주소·지도는 준비 문구를 만들어 넣지 않고 빈 상태로 둡니다.

## 앱에서 내용을 추가하는 방법

1. `청첩장`에서 예식 정보를 편집합니다.
2. `우리의 일대기`, `포토 앨범`, `신혼여행`에서 기록을 추가합니다.
3. 작성한 내용은 이 브라우저의 **기기 초안**으로 저장됩니다. 다른 기기나 다른 방문자에게 자동 공유되지 않습니다.
4. 공개할 내용이 준비되면 `내용 관리 → 공개용 파일 저장`에서 `site.json`을 내려받습니다.
5. 그 파일을 Codex에 전달하며 **“이 내용을 Wedding 저장소의 data/site.json에 반영하고 GitHub Pages에 배포해 줘”**라고 요청하면 됩니다.

공개 사이트와 저장소는 누구나 볼 수 있습니다. 공개용 파일에는 공개할 내용만 담으세요. 앱에는 로그인이나 비공개 보관함이 없습니다. 사진 파일은 브라우저 초안용으로 최대 1,000px 크기의 JPEG로 줄여 저장하므로 원본은 따로 보관해 주세요. 저장 공간이 부족하면 사진을 `assets/photos/`에 추가하고 상대 경로로 연결하는 방식을 사용하세요.

스튜디오 개인 메모·관심 표시·비교 선택은 `site.json`에 포함되지 않으며 사이트 배포를 위해 전송되지 않습니다. 브라우저 데이터를 지우면 기기 초안과 메모가 사라지므로 중요한 콘텐츠는 파일로 저장하세요.

## 백업과 추가 편의 기능

- `내용 관리 → 개인 백업 저장`은 스튜디오 개인 메모·관심·비교 선택과 여행 관심·비교·최종 선택을 보관합니다. 개인 백업 선택에서 복원할 수 있습니다. 이 파일은 공개 저장소에 올리지 마세요.
- 청첩장·일대기·앨범·신혼여행 콘텐츠 초안은 `공개용 파일 저장`으로 별도 백업합니다. 파일 불러오기는 형식을 확인하고 교체 여부를 묻습니다. 저장에 실패하면 기존 내용과 선택을 유지합니다.
- 앨범 편집에서는 사진 미리보기, 개별 삭제, 앞뒤 순서 변경, 대표 사진 지정을 지원합니다. 첫 번째 사진이 대표 사진입니다. 취소하면 기존 앨범을 유지합니다.
- 앨범과 스튜디오 사진은 화면 안에서 확대하고 이전·다음 버튼 또는 방향키로 넘길 수 있습니다.
- 신혼여행은 후보 두 곳을 나란히 비교하고 관심·최종 선택을 표시할 수 있습니다. 선택은 기기에 저장되며 개인 백업에 포함됩니다.
- 초안 작성 당시의 공개본과 현재 공개본이 다르면 안내합니다. 기존 초안은 자동으로 합치거나 지우지 않습니다. 버전 정보가 없는 예전 초안에도 안내가 표시됩니다. 먼저 초안을 백업한 뒤 새 공개본을 확인하세요.
- [방문자용 청첩장](https://gmlduqzhd123-lab.github.io/Wedding/?view=guest#/invitation)은 공개본을 표시하고 편집 버튼·개인 메모를 숨깁니다. 로그인이나 접근 권한 제한 기능은 아닙니다. 내용 관리에서도 이 링크를 열 수 있습니다.

## 브라우저 검증

추가 안정성 개선:

- 같은 브라우저의 여러 탭에서 서로 다른 항목을 수정하면 변경 내용을 합쳐 저장합니다. 같은 항목이 충돌하면 현재 입력과 다른 탭의 저장본을 보여주고 선택을 받습니다. 저장 작업은 Web Locks로 순서대로 처리합니다.
- 편집창의 오류 안내, 닫기 버튼, 저장 버튼을 스크롤과 분리했습니다. 저장 실패 시 입력을 유지하며 재시도할 수 있습니다. 저장하지 않은 입력이 있으면 닫기·이동·새로고침 전에 확인합니다.
- 사진을 이동하거나 삭제한 뒤 키보드 초점을 편집 버튼에 유지합니다. 긴 제목·이름·장소도 작은 화면 안에서 줄바꿈합니다.
- 스튜디오 자료는 별도로 불러옵니다. 자료 요청이 실패해도 청첩장과 기록 메뉴는 계속 사용할 수 있으며, 스튜디오 메뉴에서 다시 불러올 수 있습니다.
- 청첩장 링크 복사와 복사 실패 시 직접 선택할 수 있는 링크를 제공합니다. 빌드 시 공개 콘텐츠의 이름·예식 안내를 공유 미리보기에 반영합니다. 대표 이미지는 개인 사진이 없는 공통 표지이며 기기 초안과 개인 메모는 사용하지 않습니다.

`npm run check`는 콘텐츠와 개인 백업 형식, 저장 실패 시 상태 보존을 검사합니다. 개발 서버를 실행한 뒤 Playwright가 준비된 개발 환경에서 `node scripts/browser-check.mjs`로 실제 브라우저 검증을 실행할 수 있습니다. 앱에는 Playwright 의존성이 추가되지 않습니다.

별도 설치된 Playwright는 `PLAYWRIGHT_MODULE`에 `index.mjs`의 절대 경로를 지정합니다. 기본 브라우저는 Chrome이며 `BROWSER_CHANNEL`로 변경할 수 있습니다. 검증용 콘텐츠는 격리된 브라우저 컨텍스트에만 생성하고 저장소 콘텐츠는 변경하지 않습니다. 메뉴 이동, 초안 복원, 저장 실패, 개인 백업, 사진 편집, 여행 비교, 공개본 변경 안내, 방문자용 보기, 모바일 너비와 콘솔 오류를 검사합니다. 화면 캡처는 `work/browser-qa/`에 저장합니다.

`node scripts/improvements-check.mjs`는 여러 탭의 동시 저장·충돌 선택, 편집 중 닫기·이동 취소, 편집창 내 오류와 저장 재시도, 모바일 고정 버튼과 초점, 320~1280px 긴 제목, 스튜디오 오류 격리·재시도, 공유 링크와 복사 대체 화면을 검사합니다. `TEST_URL`로 배포된 사이트도 같은 격리 컨텍스트에서 점검할 수 있습니다. 추가 화면 캡처는 `work/improvement-qa/`에 저장합니다.

백업은 대기 중인 저장을 마친 뒤 최신 저장본으로 만듭니다. 대기 중 저장이 실패하면 백업을 중단하며, 이미 실패한 변경이 있을 때 저장본만 백업하려면 확인을 받습니다. 충돌 비교와 선택은 다른 탭의 추가 저장에도 유지·갱신되고, 파일 가져오기에도 같은 선택 화면을 제공합니다. 관심 표시의 연속 클릭은 누른 순서대로 처리하고 저장 중 상태를 표시합니다. 공유 대표 주소의 `?view=guest`는 청첩장으로 열리며, 사진 확대창에서는 제목이나 닫기 버튼에 초점이 있어도 방향키를 사용할 수 있습니다.

`node scripts/followup-check.mjs`는 0.8초 저장 지연을 적용한 최신 메모 백업, 대기 중 저장 실패 시 백업 중단, 관심 버튼 연속 클릭, 충돌 선택 유지·최신 내용 갱신·초점 보존, 파일 충돌의 두 해결 방법, 공유 대표 주소와 사진 방향키를 검사합니다. 같은 Playwright 환경 변수와 `TEST_URL`을 사용하며 화면 캡처는 `work/followup-qa/`에 저장합니다.

`node scripts/travel-check.mjs`는 청첩장 미입력 항목의 빈 표시, 여행 총액/날짜/비용 편집의 일관성, 예산 초과·미배분·예비비 0원, 비교 항목, 펼침·스크롤·초점 유지, 이전 형식 초안 변환, 출처 구분과 320~1440px 화면을 검증합니다. 같은 환경 변수를 사용하며 캡처는 `work/travel-qa/`에 저장합니다.

신혼여행 편집에서 숙박 지역·박 수·순서, 현지 체크인/체크아웃, 숙박 메모·일정 흐름·이동 계획을 수정할 수 있습니다. 현지 날짜를 모두 입력하면 박 수를 자동 계산하며, 날짜 순서와 박 수가 맞지 않는 파일은 가져오지 않습니다. 한국 출발/도착 날짜를 바꾸면 가안 재검토를 표시합니다. 숙박·이동을 검토한 뒤 `현재 날짜로 가안 기준 갱신`하고 초안에 저장하세요. 이 버튼은 항공편·시차나 예약을 검증하지 않으며, 지나치게 짧은 기간의 숙박 경고는 유지됩니다. 이전 백업은 기존 여행 날짜를 가안 기준으로 받아들입니다.

비용 배분이 모두 비어 있으면 `입력된 배분 없음`으로 표시하고, 직접 입력한 0원과 구분합니다. 일반 화면 상단에는 이 기기의 최종 선택과 현재 날짜·계획예산·바로가기가 표시됩니다. 방문자용 화면과 공개용 JSON에는 개인 선택이 포함되지 않습니다.

`node scripts/travel-editor-check.mjs`는 짧은 여행 기간 경고, 현지 날짜와 박 수 검증, 숙박 추가·삭제·순서 변경, 일정/이동 편집, 취소·저장·새로고침·JSON 왕복·공개본 복귀, 빈 비용/0원, 최종 선택 요약 및 방문자용 숨김, 모바일 편집창을 검증합니다. 같은 Playwright 환경 변수를 사용하며 캡처는 `work/travel-editor-qa/`에 저장합니다.

숙박 날짜의 중복·입력 순서·숙박 사이 공백과 한국 여행 기간 이탈은 편집 중과 저장 후 카드·비교표에서 경고합니다. 현지와 한국의 날짜 차이를 고려해 여행 기간의 앞뒤 1일을 허용하는 보수적인 검토 기준이며 실제 항공편·시간대를 계산한 결과가 아닙니다. 가안과 기존 백업을 보존하기 위해 이 경고만으로 저장·가져오기를 막지는 않습니다. 체크아웃 역전이나 날짜와 박 수 불일치는 기존처럼 저장·가져오기를 막습니다. `현재 날짜로 가안 기준 갱신`은 숙박 날짜 문제 경고를 없애지 않습니다.

여행지 삭제 시 해당 관심·비교·최종 선택도 정리합니다. 이전 백업이나 다른 탭에서 없어진 후보가 남아 있어도 다음 여행 선택은 현재 존재하는 후보만 계산합니다. 스튜디오의 개인 메모와 선택은 유지합니다.

기후 출처 주소는 `plan.sourceUrl`, 직접 입력한 참고 링크는 `url`로 분리합니다. 참고 링크를 편집해도 기후 기관명·자료 확인일·출처 주소는 바뀌지 않습니다. 이전 백업에 출처 주소가 없으면 임의로 참고 링크를 공식 출처로 승격하지 않으며, 메모·참고 링크 항목에 그대로 보존합니다. 스페인의 공개 숙박 가안은 기존 설명에 맞춰 바르셀로나 1박 → 마요르카 3박 → 바르셀로나 3박으로 표시합니다.

`node scripts/travel-integrity-check.mjs`는 숙박 전체 날짜 경고와 복원, 삭제·이전 백업의 비교 선택 복구, 공식 출처/개인 링크 분리, 스페인 순차 숙박, 빈 청첩장 항목과 320~1440px 화면을 검증합니다. `TEST_URL`로 배포본에도 실행할 수 있으며 캡처는 `work/travel-integrity-qa/`에 저장합니다.

`본문으로 이동`은 현재 메뉴 주소와 방문 기록을 유지하면서 본문에 초점을 옮깁니다. 편집 중 새 탭으로 여는 출처 링크는 입력창과 미저장 내용을 유지하며, 현재 화면을 떠나거나 편집창을 닫을 때는 기존의 입력 보호를 적용합니다. 이전 형식의 여행 후보도 메모 없이 참고 링크만 있으면 상세 영역에 표시합니다.

`node scripts/navigation-check.mjs`는 키보드 본문 이동 후 비교·새로고침·뒤로가기, 방문자용 메뉴 유지, 편집 중 출처 열기와 입력 보호, 이전 후보의 링크 표시 및 백업 왕복·공개본 복귀, 청첩장 빈 항목과 모바일 화면을 검증합니다. 같은 환경 변수와 `TEST_URL`을 사용하며 캡처는 `work/navigation-qa/`에 저장합니다.

중간 숙박의 날짜가 비어 있어도 입력된 체크인·체크아웃 날짜끼리 순서를 검토하며, 경고에는 원래 숙박 번호를 표시합니다. 미입력 숙박이 차지할 수 있는 기간을 임의로 공백이라고 판단하지 않습니다. 편집·카드·비교표에 같은 검토 결과를 표시하고 백업 복원 후에도 유지합니다.

여행 후보 저장 후에는 해당 후보 제목으로 초점을 돌립니다. 삭제 후에는 다음 후보, 다음 후보가 없으면 이전 후보로 이동하며, 후보가 모두 없어지면 `여행지 추가`에 초점을 둡니다. `navigation-check.mjs`는 각 위치에서 Tab으로 작업을 계속할 수 있는지도 검사합니다.

최종 선택 요약에는 해당 후보 카드와 같은 예산·숙박 검토 결과를 표시합니다. 날짜·금액·숙박 수정과 선택 변경, 새로고침·백업 복원에도 같은 입력값으로 갱신하며 방문자용 보기에는 개인 선택 요약을 표시하지 않습니다.

청첩장의 `일정 파일(.ics) 다운로드`는 현재 표시 중인 예식 일정의 `.ics` 파일을 내려받습니다. PC 또는 `.ics`를 지원하는 앱에서 가져와 등록하세요. 한국 시간의 시작 시각을 UTC로 저장하며, 미제공 이름·주소·종료 시각·알림은 생성하지 않습니다. 날짜나 시간이 비어 있으면 등록 버튼을 표시하지 않습니다. 방문자용 보기는 공개본만 사용합니다. 파일은 [RFC 5545](https://www.rfc-editor.org/rfc/rfc5545.html)의 텍스트 이스케이프·CRLF·UTF-8 줄 접기를 적용합니다.

Google 캘린더용으로는 `Google 캘린더에 추가` 링크를 제공합니다. [Google의 안드로이드 도움말](https://support.google.com/calendar/answer/37118?co=GENIE.Platform%3DAndroid&hl=ko)은 파일 가져오기를 컴퓨터에서 진행하도록 안내하므로 두 경로를 구분했습니다. 링크는 [공식 일정 추가 템플릿](https://developers.google.com/workspace/calendar/api/concepts/inviting-attendees-to-events#provide_a_link_for_users_to_add_the_event)을 사용하며, 사용자가 등록 화면에서 내용을 확인하고 저장합니다. UTC 시작 시각과 한국 시간대를 전달하며 종료 미정인 시작 일정의 자리표시자로 시작·끝에 같은 시각을 전달합니다. 실제 종료 시각이 확인된 것으로 표시하지 않으며 Google 화면에서 날짜·시간을 확인하도록 안내합니다. 실기기의 앱 전환과 저장 완료는 브라우저 링크 검사와 구분해 확인해야 합니다.

2026-11-04 실제 Google 주소에 접근한 비로그인 Chrome 검사에서 데스크톱은 일정 매개변수를 유지한 로그인 화면으로, Pixel 7 모바일 브라우저 프로필은 Google Calendar 안내 페이지로 이동했습니다. 이 브라우저 프로필 검사는 실기기 확인과 구분합니다.

같은 날 사용자가 안드로이드 휴대전화의 Google 캘린더에서 배포된 `Google 캘린더에 추가` 버튼을 실행하고, 2027-05-08 오후 1시(한국 시간)·순천아모르웨딩컨벤션 1층 일정이 올바른 내용으로 저장되었다고 확인했습니다. 검증 방식은 사용자 실기기에서의 직접 실행 및 채팅 응답입니다. Google 전용 링크의 등록 경로가 확인되었으며, `.ics` 파일의 Google 가져오기는 위 공식 도움말의 컴퓨터 경로로 안내합니다. 미제공 이름·상세 주소·실제 종료 시각은 그대로 비워 둡니다.

2026-11-08 예식일을 2027-06-05 15:00(한국 시간)으로 변경했습니다. 새 다운로드 파일·Google 등록 링크·공유 미리보기는 현재 공개 콘텐츠를 사용합니다. 이전 날짜로 이미 저장한 개인 캘린더 일정은 자동 수정되지 않으며 해당 캘린더에서 직접 수정해야 합니다. 위 실기기 확인 기록은 변경 전 날짜에 대한 이력입니다.

`node scripts/calendar-summary-check.mjs`는 최종 선택/후보 경고의 일치와 수정·선택·복원 시 갱신, 방문자용 숨김, 일정 파일의 공개본/초안 구분·시간대·빈 항목·다운로드와 미완성 일정 처리, 320~1440px 화면을 검사합니다. 같은 Playwright 환경 변수와 `TEST_URL`을 사용하며 캡처는 `work/calendar-summary-qa/`에 저장합니다.

## 로컬 실행과 검사

Node.js 24를 사용합니다. 패키지 설치는 필요하지 않습니다.

```sh
npm run dev
```

http://127.0.0.1:4173/Wedding/ 에서 확인합니다. `file://`로 HTML을 직접 여는 방식은 JSON·모듈 로딩 때문에 지원하지 않습니다. 이전에 제공된 단일 HTML 스튜디오 비교 파일과 별개의 확장형 웹앱입니다.

```sh
npm run check
npm run build
```

`check`는 콘텐츠 스키마, 30개 스튜디오·60개 이미지·연락처 매핑, JavaScript 구문과 콘텐츠 가져오기 테스트를 검사합니다. `build`는 공개할 파일만 `dist/`로 복사합니다. 로컬 서버는 개발 도구이며 실제 서비스는 GitHub Pages만 사용합니다.

## 파일 구조

```text
index.html                  앱 진입점과 공통 메뉴
assets/css/app.css          반응형 화면 스타일
assets/js/app.js            메뉴·화면·초안 편집·스튜디오 비교
assets/js/content.js        콘텐츠 검증과 날짜·링크 처리
assets/studios/             제공된 스튜디오 대표 썸네일
assets/photos/              향후 추가할 개인 사진 (필요할 때 생성)
data/site.json              공개할 청첩장·일대기·앨범·신혼여행
data/studios.json           스튜디오 정보·연락처·샘플 출처
scripts/                    개발 서버·검사·정적 빌드
tests/                      콘텐츠 저장·가져오기 검증
.github/workflows/pages.yml GitHub Pages 자동 배포
AGENTS.md                   Codex 개발 지침
```

외부 링크를 제외한 앱 경로는 모두 상대 경로이며, 화면 이동에는 `#/...`를 사용하므로 `/Wedding/` 하위 경로에서 새로고침해도 작동합니다.

## 배포

`main`에 변경 사항을 push하면 검증·빌드·GitHub Pages 배포가 실행됩니다. 저장소 Settings → Pages의 Source는 **GitHub Actions**를 사용합니다. 배포 결과는 [Actions](https://github.com/gmlduqzhd123-lab/Wedding/actions)에서 확인합니다.

GitHub Pages는 정적 파일을 제공하므로 브라우저에서 저장소에 직접 쓰는 관리자 기능이나 실시간 공동 편집은 제공하지 않습니다. API 토큰을 프런트엔드에 넣지 마세요. 공식 배포 구조는 [GitHub Pages 사용자 지정 워크플로 문서](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)를 따릅니다.
